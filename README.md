# 站点纯净模式（抖音 / B站 / YouTube）

一个 userscript，三站通用。目标是把「刷不完的推荐流」换成「搜索 → 只看这个博主 → 看完提示没有更多」，并把首页的自动播放推荐掐掉。

- **首页**：只留搜索框，推荐流整块隐藏
- **搜索页**：只看指定博主的前 4 条，4 条看完明确提示「没有更多」
- **博主 / 频道页**：显示全部视频，不做限制
- **不限每日浏览数量**（原本有个「看满 10 条自动关标签页」，已移除）

## 安装（约 3 分钟，零基础）

1. App Store 装 **Userscripts**（免费，[直达链接](https://apps.apple.com/app/id1463298887)），打开它一次
2. Safari → 设置 → 扩展 → 勾选 **Userscripts**
3. 用 Safari 打开 **[一键安装链接](https://raw.githubusercontent.com/h1284646296-rgb/site-pure/main/site-pure.user.js)**，点「安装」
4. 首次访问站点时，点扩展图标 → Userscripts → **Always Allow on This Website**，刷新

**详细图文步骤见 [INSTALL.md](INSTALL.md)。**

## 三站规则对照

| 位置 | 抖音 | B站 | YouTube |
| --- | --- | --- | --- |
| 首页 | **一个视频都看不到**（推荐流隐藏） | 首页推荐区块隐藏 | 首页推荐网格隐藏 |
| 搜索页 | 只隐藏**视频卡片**；点「**用户**」标签 → 博主列表**完整显示**（不拦截）。**不显示右侧面板** | 右侧面板列出 UP 主，点开只展开前 4 条 | 右侧面板列出频道，点开只展开前 4 条 |
| 博主/频道页 | 点进博主后，**该博主全部视频正常显示播放** | `space.bilibili.com` 全部视频 | `/@handle`、`/channel/` 全部视频 |
| 视频页 | 只显示点进去的那一个 | 播放页「相关推荐」隐藏 | 侧栏与结束推荐隐藏，`autoplay=0` |
| 顶部导航栏 | — | **首页**隐藏频道栏（番剧/直播/游戏中心…）与分区图标栏（娱乐/音乐/舞蹈…）；搜索页分区筛选**保留** | — |
| 每日浏览数量 | **不限** | 不限 | 不限 |

搜索页的「前 4 条」这个数字在脚本顶部：`var N = 4;`

## 三个站点的技术差异（为什么不能一份代码照抄）

| 站点 | 数据来源 | 播放方式 |
| --- | --- | --- |
| 抖音 | 挂钩站点自己的 `aweme/v1/web/*` 接口取 `aweme_id / play_addr / sec_uid` | **页面内浮层**播放；`play_addr` 带时效签名，过期会自动重取 |
| B站 | 挂钩 `x/web-interface/search/type` 与 `x/space/wbi/arc/search` | 新标签页打开（不走 iframe，避开跳转广告） |
| YouTube | 挂钩 `youtubei/v1/search\|browse\|next`，并能解析 `ytInitialData` | 新标签页打开（不内嵌，避免与其播放器冲突） |

B站接口带 WBI 签名，**匿名命令行请求会被 412 风控**，所以脚本不自己拼请求，只复用浏览器发出去的带签名请求。

## 抖音的两个坑（都是实测踩出来的）

写这个脚本时被抖音坑了两轮，都记在这里，免得以后重踩：

**坑 1：用户搜索结果不在 `.search-result` 容器里**

抖音搜索页的 `[data-e2e="search-result"]` 看起来是结果区，但**「用户」标签的博主列表渲染在它外面**。所以早期「展开博主后隐藏整个结果区」的做法会把用户列表一起干掉，表现为「点了用户标签，结果区一片空白」。

现在的做法：不隐藏整个结果区，只逐张隐藏**视频卡片**，并且带一个安全阀 —— 只统计**结果容器内部**的博主条目，发现就是用户标签，就什么都不隐藏。

**坑 2：视频卡片不是 `<a href="/video/">` 结构**

实测搜索页里 `a[href*="/video/"]` 数量为 **0**。所以现在有 4 条识别路径：

1. `a[href*="/video/"]`、`a[href*="/note/"]`
2. `[data-e2e*="video"]`、`[class*="search-video"]`、`[class*="video-card"]` 等属性/类名兜底
3. **结果容器的直接子元素**（按尺寸筛选）
4. 找到候选后逐级向上找「卡片级」容器，太占屏的不动

另外，抖音的验证码/风控弹层（`#captcha_container` 等）也会被隐藏并单独报告 —— 它盖在结果区上时，看起来和「结果为空」一模一样。

## 调试

在抖音搜索页，网址后面加 `&spoff=1` → **本次页面完全不做任何隐藏**（用来判断问题是不是脚本造成的）。

脚本在控制台暴露了这些入口：

| 命令 | 作用 |
| --- | --- |
| `__sp()` | 打印当前站点、页面类型、已看数量、抓到的博主 |
| `__spState` | 查看状态对象 |
| `__spRefresh()` | 立刻重绘右侧面板 |
| `__spReset()` | 清零计数与抓到的博主 |
| `__spDyPanel()` | 抖音：在页面底部显示观测面板（标签状态、各选择器命中数、疑似验证码） |
| `__spDyLog()` | 抖音：打印观测记录 JSON |

## 开发

源码拆成 5 个分片放在 `src/`，由 `build.py` 拼装成单文件产物：

```bash
python3 build.py     # src/part*.js → site-pure.user.js
python3 split.py     # 反向：site-pure.user.js → src/part*.js（改了产物后同步回分片用）
```

分片与顺序（有依赖，别调换）：`part3-adapters` → 选站 → `part1-css` → `part4-utils` → `part5-api` → `part2-core`

自检：

```bash
node --check site-pure.user.js
node selftest-sites.js      # 61 项断言，全绿
```

`selftest-sites.js` 覆盖：三站启动、页面类型识别、DOM 解析、接口解析（B站番剧被排除、YouTube `ytInitialData` 解析、抖音图文卡被排除）、时长换算、4 条上限、B站频道栏隐藏不误伤搜索框、抖音安全阀、面板开关的站点边界。

`examples/` 里放了最早那版「只针对抖音」的脚本及其自检，作为历史存档。

## 已知限制

1. **YouTube 未经真机验证**：开发环境的网络完全连不上 YouTube（TCP 都建立不了），其选择器与 `ytInitialData` 解析是按已知结构写的、并用仿真数据做了单元测试，**首次使用可能需要微调**。
2. **B站匿名接口被风控**：命令行验证时返回 412，所以脚本走「拦截浏览器自己发出的请求」这条路；真实浏览器环境可用，但未做端到端验证。
3. **B站/YouTube 的播放是新标签页打开**：不内嵌是刻意取舍 —— B站的 iframe 播放器有跳转广告，YouTube 内嵌会与其自身播放器冲突。播放页的推荐区会被隐藏。
4. **浏览计数已基本停用**：原本「左下角徽章 + 计数 + 每日限额」的那套按使用反馈移除了，只剩 v1 的运行痕迹。
5. 站点改版会让选择器失效。抖音的 DOM 大量使用带 hash 的类名（如 `tab-follow EQY455Q_...`），所以脚本一律用 `*=` 模糊匹配，尽量不写死完整类名。
